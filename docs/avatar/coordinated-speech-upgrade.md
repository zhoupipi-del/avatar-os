# 回复表演协调与完整打断

## 用户可见行为

- 等待回复期间仍可输入和发送。新消息立即中止上一轮请求和朗读。
- 输入栏的“停止回复”（聚焦时也可按 Esc）以及语音面板的“停止朗读”接入同一中止入口。
- 情绪、回复动作和口型在声音实际开始时同步启动；等待云端合成时不提前张嘴。系统语音也使用真实播放事件。
- 播放结束、失败或取消时统一释放音频资源、收嘴并退出回复动作。迟到的旧回调不能改变新一轮状态。
- 回复气泡在合成及朗读期间保留，结束后按阅读时长淡出。静音回复保留有时限的文字表演。

## 实现边界

`AgentRuntime` 为每轮输入提供 AbortSignal，传到 OpenAI-compatible / Ollama 请求及响应体读取阶段。即使适配器忽略取消，也会终止等待；旧结果不能触发身体表演、降级回复或写入对话记录。

`SpeechPerformance` 统一拥有一次朗读的身体生命周期，绑定真实声音事件，清理定时器，并拒绝旧轮事件。`CompanionVoice` 负责云端和系统声音的取消、媒体错误以及 URL / AudioContext 释放。

`VrmExpressionController.coordinate()` 在眨眼、口型写入之后、`vrm.update()` 之前协调共享 morph target：为嘴形和眨眼预留权重，再分配情绪权重。协调使用控制器原始权重，避免逐帧衰减累积。二值情绪在预算不足时让位。模型已有的 `overrideMouth` / `overrideBlink` 继续由 three-vrm 原生处理，避免重复抑制。

五元音频谱口型算法、自定义视线架构、人设和记忆模块保持现有路线。本次没有更换渲染栈或引入参考仓库依赖。

## Windows 实机验收

1. 云端合成较慢时，确认气泡保留、嘴形和回复动作等待声音开始。
2. 朗读中发送第二句，确认旧音频立即停止，只执行新回复；思考期间重复相同操作。
3. 分别用停止回复、Esc 和停止朗读打断，确认收嘴、动作复位，且之后可以继续对话。
4. 切换系统语音与克隆声音，确认实际结束事件均能释放回复状态。
5. 在自带及导入 VRM 模型上观察开心 / 悲伤、眨眼和说话叠加，确认无嘴形溢出，并检查带原生 override 的模型。
6. 静音及模拟语音服务失败时，确认不会永久卡在回复状态。
